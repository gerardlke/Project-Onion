# CS1101S Programming Methodology - Study Notes

## Topic 1: Binary Search Trees (BST)

A Binary Search Tree is a hierarchical data structure where each node has at most two children, referred to as the left and right child. The key property of a BST is that for any given node, all values in its left subtree are strictly smaller, and all values in its right subtree are strictly larger. This ordering property makes BSTs efficient for search, insertion, and deletion operations.

BST Search works by comparing the target value against the current node. If the target is smaller, we recurse into the left subtree. If larger, we recurse into the right subtree. If equal, we have found the node. In the best and average case, this runs in O(log n) time when the tree is balanced, but degrades to O(n) in the worst case when the tree becomes a linear chain — for example, when inserting already-sorted data.

BST Insertion follows the same logic as search. We traverse the tree until we find an empty position where the new value belongs, then attach a new node there. The relative order of insertions determines the shape of the tree, which directly affects performance.

BST Deletion is the most complex operation. There are three cases: deleting a leaf node (simply remove it), deleting a node with one child (replace the node with its child), and deleting a node with two children (replace the node's value with its in-order successor — the smallest value in the right subtree — then delete that successor).

Inorder traversal of a BST visits nodes in sorted ascending order. This is because inorder traversal visits the left subtree, then the current node, then the right subtree — which respects the BST ordering property. Preorder traversal visits the current node first, then left, then right, and is useful for copying or serializing a tree. Postorder traversal visits left, then right, then the current node, and is commonly used for deletion since children are processed before their parent.

## Topic 2: AVL Trees and Self-Balancing

An AVL tree is a self-balancing Binary Search Tree where the heights of the left and right subtrees of any node differ by at most one. This difference is called the balance factor, defined as height(left subtree) minus height(right subtree). A valid balance factor is -1, 0, or +1.

When an insertion or deletion causes the balance factor of any node to become +2 or -2, the tree is considered unbalanced and a rotation must be performed to restore the AVL property. Rotations are local restructuring operations that change the shape of the tree without violating BST ordering.

A Left Rotation is applied when a node becomes right-heavy (balance factor of -2) due to an insertion in the right subtree of the right child. The right child becomes the new root of the subtree, the original root becomes the left child of the new root, and the new root's original left child becomes the right child of the demoted node.

A Right Rotation is the mirror image, applied when a node is left-heavy (balance factor of +2) due to an insertion in the left subtree of the left child.

Left-Right and Right-Left double rotations are required when the imbalance occurs in the inner subtree — for example, an insertion in the right subtree of a left child. A single rotation is insufficient in these cases; first a left rotation on the child, then a right rotation on the original unbalanced node restores balance.

AVL trees guarantee O(log n) time for search, insertion, and deletion in all cases, because the height of an AVL tree with n nodes is always O(log n). This comes at the cost of the overhead of checking and updating balance factors on every mutation and performing rotations when needed.

## Topic 3: Graph Traversal

A graph is a data structure consisting of a set of vertices (nodes) and a set of edges connecting them. Graphs can be directed or undirected, and weighted or unweighted. Unlike trees, graphs may contain cycles, which means traversal algorithms must track visited nodes to avoid infinite loops.

Depth First Search (DFS) explores a graph by going as deep as possible along one branch before backtracking. Starting from a source vertex, DFS marks it as visited, then recursively visits each unvisited neighbour. DFS can be implemented recursively using the call stack, or iteratively using an explicit stack data structure. DFS runs in O(V + E) time where V is the number of vertices and E is the number of edges.

DFS has several important applications. It can detect cycles in a graph by checking whether a visited node is encountered again during traversal. It can also determine whether a graph is connected, perform topological sorting on directed acyclic graphs (DAGs), and find strongly connected components using algorithms like Kosaraju's or Tarjan's.

Breadth First Search (BFS) explores a graph level by level, visiting all neighbours of the current node before moving deeper. BFS uses a queue data structure. Starting from a source vertex, it enqueues the source, marks it visited, then repeatedly dequeues a vertex and enqueues all its unvisited neighbours. BFS also runs in O(V + E) time.

BFS is particularly useful for finding shortest paths in unweighted graphs, since it explores nodes in order of increasing distance from the source. The first time BFS reaches a node, it has found the shortest path (in terms of number of edges) to that node.

## Topic 4: Shortest Path Algorithms

Dijkstra's Algorithm finds the shortest path from a single source vertex to all other vertices in a weighted graph with non-negative edge weights. It maintains a priority queue of vertices ordered by their current known shortest distance from the source. At each step, it extracts the vertex with the smallest distance, then relaxes all its outgoing edges — updating the distance to a neighbour if a shorter path through the current vertex is found.

Edge Relaxation is the core operation in Dijkstra's algorithm. For an edge from vertex u to vertex v with weight w, relaxation checks if dist[u] + w < dist[v]. If so, dist[v] is updated to dist[u] + w and v's position in the priority queue is updated. This process propagates improvements through the graph until all shortest paths are found.

Dijkstra's algorithm runs in O((V + E) log V) time when implemented with a binary heap priority queue. It does not work correctly with negative edge weights because it assumes that once a vertex is extracted from the priority queue, its shortest distance is finalised — an assumption that breaks when negative edges can offer shorter paths through already-processed vertices.

The Bellman-Ford Algorithm solves the single-source shortest path problem for graphs that may contain negative edge weights. It works by repeatedly relaxing all edges V-1 times, where V is the number of vertices. After V-1 iterations, all shortest paths are found if no negative cycles exist. A V-th iteration is then performed; if any distance still decreases, the graph contains a negative cycle. Bellman-Ford runs in O(VE) time, making it slower than Dijkstra for non-negative graphs.

## Topic 5: Dynamic Programming

Dynamic Programming (DP) is an algorithmic technique for solving problems that have two key properties: overlapping subproblems and optimal substructure. Overlapping subproblems means the same subproblem is solved multiple times in a naive recursive solution. Optimal substructure means the optimal solution to the overall problem can be constructed from optimal solutions to its subproblems.

Memoization is a top-down DP approach. A recursive function is written naturally, but the result of each subproblem is stored in a cache (usually a hashmap or array) the first time it is computed. On subsequent calls with the same input, the cached result is returned immediately rather than recomputing. This converts an exponential-time recursion into a polynomial-time computation.

Tabulation is a bottom-up DP approach. Instead of recursing from the top, we identify the smallest subproblems, solve them first, and iteratively build up solutions to larger subproblems using previously computed results stored in a table. Tabulation avoids recursion overhead and is often more cache-friendly than memoization.

The Fibonacci sequence illustrates DP clearly. The naive recursive solution recomputes fib(n-2) and fib(n-1) exponentially many times, giving O(2^n) time complexity. With memoization, each value is computed once and cached, reducing complexity to O(n). With tabulation, we fill a table from fib(0) and fib(1) upward, also achieving O(n) time and allowing O(1) space with two variables.

The 0/1 Knapsack Problem demonstrates DP on combinatorial optimisation. Given a set of items each with a weight and value, and a knapsack with a maximum weight capacity, the goal is to select items to maximise total value without exceeding capacity. Each item is either included (1) or excluded (0) — it cannot be fractionally included. The recurrence relation is: dp[i][w] = max(dp[i-1][w], dp[i-1][w - weight[i]] + value[i]), where dp[i][w] is the maximum value achievable using the first i items with weight limit w.

Longest Common Subsequence (LCS) is a classic DP problem. Given two strings, the LCS is the longest sequence of characters that appears in both strings in the same relative order (but not necessarily contiguously). The recurrence is: if characters match, LCS(i,j) = 1 + LCS(i-1, j-1); otherwise, LCS(i,j) = max(LCS(i-1,j), LCS(i,j-1)). This runs in O(mn) time and space where m and n are the lengths of the two strings.

## Topic 6: Recursion and the Call Stack

Recursion is a programming technique where a function calls itself with a smaller or simpler input, working toward a base case that terminates the recursion. Every recursive call adds a new stack frame to the call stack, containing the function's local variables and return address. When the base case is reached, the stack unwinds — each frame resolves and returns its result to the caller above it.

The Base Case is the condition under which a recursive function returns a result directly without making further recursive calls. Without a correct base case, recursion continues indefinitely until a stack overflow error occurs, as the call stack grows beyond its allocated memory limit.

Tail Recursion is a special form of recursion where the recursive call is the very last operation in the function — no computation is performed on the returned value. Tail-recursive functions can be optimised by compilers into iterative loops (tail call optimisation), reusing the same stack frame instead of adding a new one, which eliminates stack overflow risk for deep recursions.

Tree recursion occurs when a function makes more than one recursive call per invocation. Fibonacci computed naively is a tree-recursive process — each call spawns two more calls, leading to exponential growth in the number of calls. Tree recursion is natural for problems with branching structure (like tree traversal) but inefficient when subproblems overlap — which is precisely where Dynamic Programming provides improvement.
